# Codex Guard 软件映射说明

软件映射的目标是让 `CodexWorker` 尽量复用 admin 已经安装的**系统级程序文件**，同时保持两个 Windows 用户的配置、登录和敏感数据相互隔离。它不是账户克隆，也不是静默安装器。

## 四类结论

| 分类 | 含义 | Codex Guard 行为 |
|---|---|---|
| 直接共用 | 安全的系统级 EXE 和公共快捷方式已经存在 | 只显示事实，不写入 |
| 创建快捷方式 | Program Files 或固定 NTFS 卷上的安全共享 EXE 已存在，但 Worker 没有公共入口 | “勾选全部可映射”后，经一次 UAC 批量创建无参数公共 `.lnk` |
| 现有包需注册 | Store/MSIX 等按用户注册应用 | 复用本机现有包完成 Worker 注册；快捷方式无法替代注册 |
| 技术阻断 | admin 用户资料、主 EXE 缺失、启动参数不透明或安全边界不满足 | 不生成已知失效或越权入口，也不建议重新下载 |

“软件一致”只表示尽量使用同一份程序主体。以下内容仍然按用户分开：

- `%APPDATA%`、`%LOCALAPPDATA%` 设置和缓存；
- 登录令牌、浏览器资料、插件和扩展；
- 按用户保存的许可证、最近文件和任务记录；
- Microsoft Store/MSIX 的用户注册状态。

## 自动映射必须同时满足

1. 目标是存在的本地绝对 `.exe`；
2. 目标位于 `Program Files`/`Program Files (x86)`，或位于本机固定 NTFS 卷；
3. 非 Program Files 目标从其父目录直到盘根都必须通过 ACL 核验；
4. 目标及父路径不含重解析点，EXE 只有一个硬链接；
5. 目标和父目录不允许 Worker、Worker 本地组、Sandbox 或宽泛用户组写入；
6. 入口不是安装器、卸载器、修复器或更新器；
7. 原入口不需要启动参数；
8. 提升后的管理员阶段重新扫描后，名称、发布者、清单 ID 和路径仍完全一致。

任一条件不满足，项目都不会出现为可勾选的自动映射对象。这里采用有意保守的失败关闭策略；主 EXE 无法可靠识别的软件需要 admin 人工处理。

## 操作

1. 打开 Codex Guard →“软件映射”→“重新扫描”。
2. 可先“导出 CSV 清单”进行人工核查。CSV 只含显示名称、版本、发布者、位置、来源和建议；公式前缀会被中和。
3. 点击“勾选全部可映射”；技术阻断项不会被勾选。
4. 点击“UAC 创建勾选快捷方式”，一次最多处理 128 项。
5. 在安全桌面输入 admin 凭据。
6. 核对确认窗里的每个发布者和完整 EXE 路径，输入四位码。
7. 结果位于公共开始菜单：

   ```text
   C:\ProgramData\Microsoft\Windows\Start Menu\Programs\Codex Guard - Shared Software
   ```

8. 在 Worker 下首次打开并完成该软件自己的用户配置或许可证流程。

## 明确禁止

- 不把 `C:\Users\admin\AppData` 共享、复制或建立联接；
- 不复制或接管 `C:\Program Files\WindowsApps`；
- 不读取/执行注册表中的 `UninstallString`；
- 不复制带参数的快捷方式命令行；
- 不自动运行安装器、修复器、更新器或卸载器；
- 不删除、移动或覆盖程序文件。

如果软件只位于 admin 的 `AppData\Local\Programs`，现有“admin AppData 无访问”策略会优先阻断它。仅创建 `.lnk` 无法改变这个事实；若自动放宽该目录，又会把 admin 的应用数据边界暴露给 Worker。因此“软件映射”仍将其标为技术阻断。0.5.0 起可转到独立的“离线复用”页：经 UAC 只复制单一程序目录到 Worker 的 `Local\Programs`，目标必须不存在，且不迁移整个 AppData、注册表或令牌。详见 [离线复用说明](OFFLINE_REUSE.md)。
