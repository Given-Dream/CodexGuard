# Codex Guard 离线复用说明

离线复用的目标是尽量利用本机已经存在的程序文件、安装介质和 Windows 包载荷，让 `CodexWorker` 获得可运行的软件环境，同时避免再次下载大体量软件。它不是用户资料克隆器，也不保证复制 admin 的登录、许可证或个人设置。

## 六类结论

| 分类 | 含义 | Codex Guard 行为 |
|---|---|---|
| 直接复用 | 机器级或安全共享程序已存在 | 不复制、不安装；转到“软件映射”创建入口或直接运行 |
| AppData 可提取 | 主程序位于 `admin\AppData\Local\Programs\单个应用` | 可通过 UAC 只复制到 Worker 的 `Local\Programs` |
| 本地介质可用 | 注册表中的 `InstallSource` 仍存在 | 显示本地路径；不自动执行安装器 |
| 现有包需注册 | Store/MSIX 按用户注册 | 提醒复用现有包载荷；不复制 WindowsApps |
| 权限/路径待核查 | EXE 存在，但 ACL、路径或启动参数不满足自动规则 | 不下载；由 admin 核对后重新扫描 |
| 本地载荷待定位 | 未找到主 EXE 或已存在介质 | 先搜索 D/E/F 盘与厂商缓存，最后才考虑下载 |

## 自动复制的严格范围

只有满足以下条件的项目才可勾选：

1. 主 EXE 是 `admin\AppData\Local\Programs` 的严格后代；
2. 每次只取该目录下一个顶层应用文件夹，不能选择整个 `Programs` 或 AppData；
3. 源根、祖先和后代不含重解析点，文件不是多硬链接；
4. 提升后的管理员阶段重新扫描后，清单 ID、名称、发布者、源根和相对 EXE 仍完全一致；
5. Worker 资料路径同时匹配受保护状态和 Windows ProfileList；
6. 固定目标 `CodexWorker\AppData\Local\Programs\<原顶层目录名>` 尚不存在；
7. 单批不超过 64 个应用、250,000 个文件或 200 GB，磁盘还需额外保留 512 MB；
8. 用户关闭 Codex、终端、Git 和 WSL 后，通过 UAC 安全桌面及四位确认码批准。

复制时源文件以只读句柄打开并拒绝并发写入，目标目录和文件采用 `CreateNew`。任何目标存在都会停止；不会合并、覆盖、移动或删除。复制完成后记录文件数、字节数、聚合 SHA-256、主 EXE SHA-256 和 Worker 快捷方式。

失败时不会自动回滚或清理。任何部分副本保持管理员控制并在审计清单中标为 `PARTIAL_REVIEW_REQUIRED`，由 admin 人工核查。这样可以避免异常处理再次触发范围错误的删除操作。

## 不自动迁移注册表的原因

`HKCU` 属于具体 Windows 用户。完整复制 admin 的注册表会同时带入自启动、绝对用户路径、令牌、许可证密文、浏览器和 Shell 集成；DPAPI 内容也不能由 Worker 原样使用。因此本版本采用以下顺序：

1. 先复制程序主体；
2. 以 Worker 首次运行，让软件生成自己的 HKCU；
3. 若失败且已有本地安装源，由 admin 使用厂商介质进行离线注册/修复；
4. 仅在明确了解厂商键值时人工迁移少量非敏感设置。

绝不复制 `NTUSER.DAT`、整个 HKCU、整个 AppData、`Run/RunOnce`、登录令牌、Cookie 或 Codex 本地记录。

## 操作步骤

1. 在 admin 会话打开已安装的 Codex Guard，进入“离线复用”。管理员身份的扫描能看到 admin 用户注册表和 AppData；沙箱只读查看可能不完整。
2. 点击“重新盘点”，先导出“模拟迁移 CSV”。
3. 对“直接复用”项目使用“软件映射”；对“本地介质可用”项目保留路径，仅在实际启动失败时离线修复。
4. 点击“勾选 AppData 可提取项”，人工核对每个源目录。
5. 完全退出 Codex、终端、Git 和 WSL，点击“UAC 准备 Worker 本地副本”。
6. 在管理员确认窗核对源、固定目标、文件数和大小，勾选边界声明并重新输入四位码。
7. 完成后以 CodexWorker 首次启动软件，检查保存、插件、许可证和用户配置。
8. 审计清单位于：

   ```text
   C:\ProgramData\Codex Guard\OfflineReuse
   ```

## 特权软件例外

Docker Desktop/Podman Desktop 的程序文件无需重新下载，但不能为了“可用”而自动把 CodexWorker 加入 `docker-users` 等宿主控制组。容器守护进程通常能够挂载宿主路径或控制高权限服务，会削弱甚至绕过 NTFS 隔离。此类软件应使用隔离虚拟机或 admin 人工管理的远程执行端。

Store/MSIX 注册、驱动、服务、COM、许可证和带特殊参数的启动器仍然需要厂商支持的注册步骤。本地载荷存在意味着通常不必重新下载，但不等于快捷方式可以替代注册。
